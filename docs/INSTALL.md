# 安装与日常使用

**安装后看不到面板，先确认有没有点进具体小节。** 课程首页和章节目录通常不显示面板；进入正文有视频、文档或检测的学习页后再检查。[查看 README 的逐步使用引导](../README.md#第一次使用从哪里打开学习助手)。

第一次使用先安装脚本；不接入 AI 可直接开始，自动答题才需要配置和测试接口。想先了解自动流程，可阅读 [完整功能说明](FEATURES.md)。

## 安装前准备

下面的接口准备只针对需要自动答题的用户。不接入 AI 可直接跳到“安装脚本”。

1. 如需自动答题，选择 AI 服务商，在其开发者控制台创建自己的 API Key。
2. 从控制台复制可用的模型 ID，核对接口区域、余额，以及模型是否支持图片输入。聊天网页里的模型名称未必能用于 API。
3. 确认电脑可以访问接口。脚本不会修改代理设置，也不会改变账号的地区或模型权限。
4. 保存接口时选择用于文字、图片或两者；图片用途需支持图片输入，没有图片接口时会记录跳过图片题。

## 安装脚本

1. 安装官方 [Tampermonkey（油猴）](https://www.tampermonkey.net/) 扩展。按扩展提示允许用户脚本运行；不同浏览器版本可能显示“允许用户脚本”或要求开发者模式，见 [官方说明](https://www.tampermonkey.net/faq.php?locale=zh#Q209)。
2. 点击 **[下载 ZIP](https://github.com/Flyer2333/xuexitong-ai-assistant/archive/refs/heads/main.zip)**，下载完成后右键 ZIP → **全部解压**。也可以在仓库首页点击 **Code → Download ZIP**。
3. 打开解压出来的文件夹，进入 `dist`，找到 `xuexitong-ai-assistant.user.js`。右键文件 → **打开方式 → 记事本**。不需要运行这个文件。
4. 在记事本中按 `Ctrl+A`、`Ctrl+C`，复制全部代码。
5. 点击浏览器工具栏中的油猴图标 → **添加新脚本**。编辑器中按 `Ctrl+A` 删除默认示例，再按 `Ctrl+V` 粘贴全部代码，最后按 `Ctrl+S` 保存。
6. 回到油猴管理面板，确认脚本名称为“超星学习通自动化脚本（支持接入各种主流AI模型api）”、版本为 **1.4.8**，并且已启用。停用其他控制同一课程页的脚本，再刷新课程页。

若此前手动安装了本地临时验证号 **1.4.9**，请用正式 **1.4.8** 的代码覆盖现有脚本并保存；自动检查更新不会降版本。正式版保留同样的音频播放与静音修正，原保存的接口设置可继续使用。

已安装旧版的用户，请按[安装后的更新方法](UPDATES.md)覆盖升级一次。1.0.9 起提供油猴更新地址与面板入口，后续不用每次重新添加脚本。
7. 打开学习通课程，点击“章节”，再点击一条具体小节名称。进入视频、文档或检测的学习页后，查看右下角“学习助手”；如果安装时这个学习页已经打开，请先刷新。不要停在只有章节列表的目录页。
8. 面板出现后，只处理视频和阅读可选择“不接入 AI”并直接开始；需要自动答题则切换为“接入 AI（自动答题）”，继续下方配置。标题下方“外观”可切换默认、奶龙、奶蛙皮肤并保存选择。

运行前请选中课程标签，保持窗口可见，不最小化，也不要让电脑休眠。后台运行可能延迟弹题和“继续学习”处理；专题阅读打开独立标签后应保持阅读标签在前台。原因及恢复方法见 [前台运行说明](../README.md#建议将课程页保持在前台)。

### 可选：通过 Raw 直接安装

打开仓库中的 `dist/xuexitong-ai-assistant.user.js`，点击 **Raw**。如果油猴成功弹出脚本安装页，核对名称和版本后确认安装即可。

如果一直停在 `tampermonkey.net/script_installation.php`，说明安装中转尚未完成；仅凭这个页面无法判断具体的权限或网络原因。请改用上面的 ZIP 手动添加方法，不要复制中转页的文字或 GitHub 文件预览页的 HTML。

**源码 ZIP 不是油猴备份包。** 不能把整个源码 ZIP 直接用于油猴备份恢复；要先解压，再按上述步骤复制 `.user.js` 代码。不同名称或命名空间的旧脚本可能仍同时运行，安装新版不会自动停用它们。

## 不接入 AI 直接使用

运行模式选择“不接入 AI”，点击“开始自动”，无需填写 Key 或测试连接。题目不作答，记录后继续；视频弹题阻止播放时跳过受阻视频，平台可能仍记为未完成。结束后查看跳过记录，详见 [无 AI 模式功能与限制](../README.md#不接入-ai也能做什么)。

## 配置 AI

1. 展开“AI 接口设置”。
2. 选择服务商，面板会填入预设协议和地址，并显示模型下拉列表。Key 需要使用自己的账号创建。
3. Base URL 填厂商文档对应的基础路径，例如 OpenAI 为 `https://api.openai.com/v1`。不要加 `/chat/completions` 或 `/responses`。
4. 从下拉框选择模型；没有所需型号时选“没有我要的模型，手动填写”，填入控制台完整 ID。填写 API Key。选择接口用途并保存。一个模型可兼顾文字和图片；手动型号请自行核对能力，图片用途需要支持图片输入。
5. 初次使用先不勾选 JSON 模式，推理设置保持默认。选项按当前模型适配；有的模型支持强度档位，有的只支持开关，有的只能使用默认值。具体见[模型目录](MODELS.md)。
6. 最大输出默认 8192 token，实际消耗按请求计算。推理过程也可能占用输出预算；若返回空内容，可尝试增加上限或降低推理强度。
7. 点击“保存设置”。配置同时加入默认折叠的“已保存接口”；可按服务商、模型和遮挡密钥区分多组配置，并切换用途或删除。Key 输入框会清空，只显示已保存提示。同一服务商、协议和地址下，留空保存会保留原 Key；更换其中任一项后，需要重新输入 Key。
8. 点击“测试 AI”。API 模式会发送一条短请求，可能收费。测试成功表示文字请求和 JSON 返回正常，图片能力和答案正确性仍需另行确认。

## 开始、停止和更新

- 同标签同课程中，已明确开启的自动运行可在刷新后接续；停止或报错取消接续，新标签或新课程不会自动开始。
- 点击“开始自动”，脚本会按当前页面处理视频、文献或检测。视频弹题答对后恢复当前视频，同页多个视频逐个处理，之后处理文献、专题和检测；本章能处理的内容依次完成。AI 模式下未知、未完成或无响应内容先自动测试并重新开始一次；仍失败记录跳过。无 AI 模式不测试，直接记录无法处理项，继续其余任务或下一节。
- 面板的“静音播放”默认开启，取消后尝试有声播放，选择会保存。若浏览器阻止有声自动播放，请手动播放或重新勾选静音后开始。
- 章节重做若重复失败答案，最多增加两次 AI 复核，可能增加用量；仍重复时尝试未提交组合。它不代表平台已确认答案正确。
- 可以先在章节检测使用“仅看答案”，查看状态中的答案；图片题可展开截图预览检查题干，确认后再开始自动。
- 停止会取消模型请求并阻止后续填写；已经发出的请求可能仍被服务商计费。
- 夜间暂停按北京时间而非设备系统时区。页面关闭、电脑休眠、浏览器冻结后不会按点执行恢复。
- 检查到新版本后，面板顶部会出现提醒；可点 × 关闭本版本提示，或延后 6 小时，不会强制更新或中断课程。更新时可在油猴中检查脚本更新，或使用面板的“脚本更新”入口，安装后刷新具体章节学习页。无法直接更新时，可按[更新教程](UPDATES.md)使用 ZIP 备用方法。

## 使用专题阅读

课程显示“去阅读”时，开始自动后会在新标签打开专题目录。请让阅读标签保持前台并获得焦点，每项累计 90 秒；切走会暂停计时。进度会保存，刷新或重新开始后可接续。读完后脚本关闭本次打开的阅读标签，回原课程先找本章检测；没有自动切回时请手动切回。

专题页也需要启用同一个脚本。如果阅读页没有接入、目录或正文识别失败，原课程面板会提示原因。目录变黄和本地计时结束不代表平台已记录完成。

## 本地 Codex 连接

**已配置 API 的用户可以跳过这一节。** 下面以 Windows 为例，教你把浏览器脚本连到本机的 Codex CLI。

连接过程是：**浏览器脚本 → 本地连接服务 → Codex CLI**。你需要先在电脑上启动本地服务，再把服务的地址和连接码填进脚本；使用期间保持服务窗口打开。

### 第 1 步：确认电脑具备运行条件

需要安装 **Node.js 20.11 或更高版本**（含 npm），以及已经登录的 **Codex CLI（命令行版）**。仅安装或登录桌面版 Codex，还不能确认命令行版可用。

打开 PowerShell，逐行输入以下命令，每行输完按回车：

```powershell
node --version
npm --version
codex --version
codex login status
```

前三条应显示版本号，最后一条应显示已登录状态。如果提示找不到命令，先完成对应安装：[Node.js 下载](https://nodejs.org/zh-cn/download)、[Codex CLI 安装说明](https://learn.chatgpt.com/docs/codex/cli)。安装后关闭并重新打开 PowerShell，再检查一次。

如果 Codex 尚未登录，运行 `codex login`，按提示完成登录后，再运行 `codex login status` 核对。具体登录方式见 [Codex 官方登录说明](https://learn.chatgpt.com/docs/auth)。这几条检查命令不会发送答题请求。

### 第 2 步：下载、解压，找到有 package.json 的文件夹

1. 点击 **[下载本地服务 ZIP](https://github.com/Flyer2333/xuexitong-ai-assistant/archive/refs/heads/main.zip)**。下载完成后，在浏览器下载列表中点“在文件夹中显示”，找到 `xuexitong-ai-assistant-main.zip`。
2. 回到下载文件夹，**右键 ZIP 文件 → 全部解压 → 选择 D 盘的目标文件夹 → 点击“解压”**，等待解压完成。双击 ZIP 只是查看里面的内容，不会把文件解压出来。
3. 打开解压出的文件夹，找到下面这一层。**`package.json`、`src` 和 `docs` 必须能在同一个窗口里看到。** 如果里面只有一个同名文件夹，再双击进去一层。

**先检查地址栏，再打开终端：路径里不能有 `.zip\`。** ZIP 预览窗口也能显示 `package.json`、`src`、`docs`，仅看到这些文件还不能证明已经解压。如果文件列表出现“压缩率”“压缩后大小”等列，也说明你仍在压缩包里。

```text
仍在压缩包里：…\xuexitong-ai-assistant-main.zip\xuexitong-ai-assistant-main
已解压的目录：D:\学习通助手\xuexitong-ai-assistant-main
```

第二行只是路径示例，以你实际选择的解压位置为准。

```text
xuexitong-ai-assistant-main
├─ package.json     ← 找到这个文件，停在这一层
├─ src
├─ docs
└─ …
```

如果 Windows 隐藏了文件扩展名，`package.json` 可能只显示为 `package`。可在资源管理器中开启“查看 → 显示 → 文件扩展名”。

### 第 3 步：从这个文件夹打开 PowerShell，并核对位置

确认当前是第 2 步中**地址不含 `.zip\` 的普通文件夹**，在文件夹空白处右键，选择“在终端中打开”；Windows 10 也可按住 `Shift` 再右键，选择“在此处打开 PowerShell 窗口”。

也可以按 `Alt+D` 选中顶部地址栏，输入 `powershell` 并回车。这个方法需要真实文件夹；在 ZIP 预览窗口里使用，可能无法带入目录，打开后仍停在 `PS C:\>`。

在新打开的 PowerShell 窗口中，先运行：

```powershell
Test-Path .\package.json
```

**看到 `True` 才继续下一步。** 如果显示 `False`，回到第 2 步，确认已解压并进入含 `package.json` 的真实文件夹；重新在那里打开终端，或使用下面的备用方法切换目录。

**备用方法：手动切换目录。** 如果终端仍停在 `PS C:\>`，回到已经解压的普通文件夹，按 `Alt+D`、`Ctrl+C` 复制完整路径。再回到 PowerShell，运行下面这行后，按提示粘贴路径并回车：

```powershell
Set-Location -LiteralPath ((Read-Host '请粘贴解压后、含 package.json 的文件夹路径').Trim('"'))
```

然后重新运行 `Test-Path .\package.json`，返回 `True` 后再启动服务。不要粘贴包含 `.zip\` 的路径。

> 如果提示符是 `PS C:\>`，不要直接运行启动命令。npm 会在终端当前文件夹中查找 `package.json`；找不到时，就会报你截图中的 `ENOENT`、`C:\package.json` 错误。只复制下方代码框内的命令，不要把 `PS …>` 一起复制。

### 第 4 步：启动本地服务，确认启动成功

在刚才返回 `True` 的同一个窗口中运行：

```powershell
npm run start:codex
```

此服务使用 Node.js 自带模块，按本教程启动无需先运行 `npm install`。

接下来会依次出现两个菜单：

1. **选择答题模型**：按 `↑` / `↓` 移动，按 `Enter` 确认。
2. **选择推理强度**：同样用方向键选择、回车确认。菜单只显示当前模型返回的强度；不确定时选择“模型默认强度”。

两次确认后，服务会自动启动。按 `Esc` 或 `Ctrl+C` 可取消，此时不会启动服务。首次需要读取本机 Codex 的模型目录，请稍等；若读取失败，按终端提示检查 CLI 安装、版本、登录及网络后重试。

启动成功后，终端应出现以下两类信息，第二行会显示你电脑上的实际文件路径：

```text
学习检测 Codex 本地服务：http://127.0.0.1:18763
连接码保存在：…\src\local\bridge-token.txt
```

**看到这两行后，让窗口保持打开，不用继续输入命令。** 窗口一直停在这里是正常的，表示服务正在等待浏览器连接。此时只能确认本地服务已启动，还没有调用 Codex 答题。

### 本地 Codex 的模型怎么选？

**现在直接在启动菜单里选，不需要手写模型名和强度。** 面板里的 API 模型下拉框、桌面版 Codex 当前会话的模型选择，都不会直接替这个服务切换模型。

模型列表和各模型支持的强度来自本机 Codex CLI 的目录。目录可能来自缓存，能看到某个型号不等于账号调用权限已验证；实际可用范围受账号、登录方式和客户端版本影响，见 [官方模型说明](https://learn.chatgpt.com/docs/models)。图片题应选支持图片输入的模型；明确只支持文字的条目会标“仅文字”。

菜单会记住上次完成选择的模型和强度，下次自动定位到它们，仍需回车确认。更换模型时只显示新模型支持的强度，不沿用不兼容的旧强度。偏好保存在 `src/local/codex-launcher.json`，不会修改你的个人 Codex 配置或连接码。

选择“使用 CLI 默认模型”表示不指定型号；选择“模型默认强度”表示不指定强度。服务不读取个人 `config.toml`，因此这里的默认不代表桌面端当前会话设置。

启动后，终端会显示你选择的模型和强度。**这不是模型调用成功的证明**；实际调用时仍会检查账号权限和模型可用性。

**已经保存了“本地 Codex”配置，怎么换模型？**

保留面板中的那张配置卡片，在服务窗口按 `Ctrl+C`，重新运行 `npm run start:codex`，在菜单里选择新模型和强度即可。只要服务地址、端口和连接码没有变化，原来保存的文字 / 图片用途继续使用，无需删除配置或重新填写 Key。卡片上的 `codex` 标签不代表服务此刻实际使用的模型；模型设置以服务启动时读取的值为准，实际调用是否成功仍需看调用结果。

更换后点击“测试 AI”，会实际调用所选模型验证文字和已选择的图片用途；测试消耗账号或接口的模型用量。若同时更改了端口、连接码或换用另一份服务文件夹，则需要核对并更新面板中的地址和 Key。

### 第 5 步：找到连接码，填入浏览器脚本

回到第 2 步的文件夹窗口，依次打开 **`src` → `local` → `bridge-token.txt`**，用记事本打开文件，复制里面的一整行连接码。这个文件会在首次启动服务时自动生成。

回到学习通具体章节页，展开脚本面板的“AI 接口设置”，按下表填写并保存：

| 面板项目 | 填什么 |
| --- | --- |
| 服务商 / 接入方式 | 选择“本地 Codex” |
| Base URL | `http://127.0.0.1:18763` |
| Key | 刚复制的 `bridge-token.txt` 中的连接码 |

这里的 Key 用来验证浏览器对本地服务的访问，**填本地连接码即可**。不要上传或分享这个文件及其内容。

### 第 6 步：点击一次，测试文字和图片

保持服务窗口打开，在脚本面板点击 **“测试 AI”**。本地 Codex 会先检查地址和连接码，再实际调用启动菜单里选中的模型：

- **用于文字的接口：** 回答一道随机简单加法，结果正确才显示“文字 · GPT · 测试通过”。
- **用于图片的接口：** 识别一张随机六位数字图片，数字完全匹配且置信度足够才显示“图片 · GPT · 测试通过”。未选择图片接口时不发送图片测试。
- 同时使用文字和图片时，一次点击依次完成两项，不需要再点第二个按钮；某项失败会单独说明，已通过的另一项结果保留。

**这次测试会实际消耗所选账号或接口的模型用量。** 测试过程中按钮显示“正在测试…”，下方立即出现等待说明、当前阶段和已用秒数。CLI 启动、联网及文字/图片串行推理会增加等待，可能需要数十秒或更久；请保持 PowerShell 服务窗口开启，不必重复点击。可点击“停止”取消；夜间休息期间不发起测试。通过仅代表本次简单测试成功，不保证所有课程题目都能识别或答对。

文字测试通过后自动切换到 GPT 主题，即使之前选过默认或奶龙/奶蛙，也无需再手动开启。其他已支持的 AI 文字模型同样自动匹配自己的主题；之后可以手动切换，下次测试通过时再自动匹配。结果显示服务选中的模型与推理强度。测试通过后再按需使用“仅看答案”或“开始自动”。如果失败，按下方排错表检查，并查看本地服务窗口中的错误。

### 已经运行旧版本地服务，怎么更新？

把油猴脚本更新到 **1.4.8**，刷新具体章节页，再点击“测试 AI”。新版图片测试使用原有的 `/solve` 答题接口；能正常截图答题的旧服务，不需要仅为这项测试重新下载、重启或更换连接码。原保存的文字/图片用途保留。

接口设置里的“测试图片识别（可能计费）”仍可用于单独复测图片。需要菜单或其他服务端更新时，再更新服务源码、保留 `src/local` 并重启。

### 下次使用时怎么启动、结束时怎么关闭

文件保留在原处时，下次无需重新下载或复制连接码。按第 3、4 步，在有 `package.json` 的文件夹内运行 `npm run start:codex`，确认菜单中上次的模型和强度即可；如果面板中保留了之前的地址和连接码，也无需重填。

关闭 PowerShell 窗口，或在服务窗口按 `Ctrl+C`，都会停止本地服务。如果 Windows 随后询问 `Terminate batch job (Y/N)?`（是否终止批处理），输入 `Y` 并回车。浏览器随后无法连接时，先检查服务是否仍在运行。

<summary>遇到报错时，展开按提示排查</summary>

| 看到的提示 | 处理方法 |
| --- | --- |
| `ENOENT`、找不到 `package.json` | 回到第 2、3 步，从正确文件夹打开 PowerShell；确认 `Test-Path .\package.json` 返回 `True` 后再启动。无需为此重装 npm。 |
| `npm.ps1` 无法加载，系统禁止运行脚本 | 使用 `npm.cmd --version` 检查 npm；第 4 步改用 `npm.cmd run start:codex`，无需修改系统执行策略。 |
| 找不到 `node`、`npm` 或 `codex` 命令 | 回到第 1 步检查安装，安装后重新打开终端。已安装 CLI 但服务仍找不到它时，见下面的高级设置。 |
| `EADDRINUSE`、端口已被占用 | 检查是否已在另一个窗口启动过本服务；已有服务时直接使用。不要重复开多个服务；其他程序占用时可按高级设置改端口。 |
| 连接失败 | 检查服务窗口是否仍在运行，以及 Base URL 是否与服务窗口显示的一致。 |
| 401、连接码无效 | 重新打开当前这份服务文件夹里的 `src/local/bridge-token.txt`，复制完整连接码，填入 Key 并保存。 |
| 连接测试通过，但实际答题失败 | 查看服务窗口中的 Codex 错误；先核对第 1 步的 CLI 登录状态，再检查所用模型、账号额度和网络。简单测试通过不代表复杂题目、后续请求或剩余额度始终正常。 |

</details>

<details>
<summary>高级设置：指定 Codex 路径、模型、推理强度或端口</summary>

通常只需使用启动菜单。无人值守或已有环境变量脚本需要直接启动时，可在启动前设置变量，再运行 `npm run start:codex:direct`，跳过菜单；原有 `npm run start:codex` 现在始终打开选择菜单。

例如账号可用相应型号时，可这样直接启动：

```powershell
$env:XXT_CODEX_MODEL = "gpt-6.1-sol"
$env:XXT_CODEX_REASONING = "medium"
npm run start:codex:direct
```

环境变量仅对当前 PowerShell 及它启动的服务有效，修改后需重启。菜单启动时，已有模型环境变量只用于定位初始选项，最终以本次菜单确认结果为准。

| 环境变量 | 用途 |
| --- | --- |
| `XXT_CODEX_BIN` | 服务找不到 Codex 时，填入电脑上 Codex CLI 的原生可执行文件完整路径。Windows 下不要填写无法直接执行的 `.cmd` 包装器路径。 |
| `XXT_CODEX_MODEL` | 直接启动时指定 CLI 模型；留空则不传模型参数。交互启动可用菜单选择。 |
| `XXT_CODEX_REASONING` | 指定所选模型支持的推理强度；留空则不传强度参数。服务不读取个人 `config.toml`。 |
| `XXT_CODEX_PORT` | 更改本地服务端口，默认 `18763`。改动后，面板中的 Base URL 也要改成相同端口。 |

面板中的 API 模型和推理选项不会改变本地 Codex 服务的配置。服务只监听本机回环地址。

</details>

## 常见问题

| 现象 | 排查 |
| --- | --- |
| 没有面板 | 检查扩展启用、域名匹配、用户脚本权限；刷新，停用旧脚本 |
| 401 | 核对该厂商 Key；Codex 模式核对本机连接码 |
| 403 | 账号模型权限、地区资格、网络拦截；不要反复重试 |
| 404 | Base URL/模型 ID/区域或接入点不一致 |
| 400 | 换成模型支持的协议；关 JSON/推理参数；文字模型不要传图 |
| 429 | 服务商限流或余额不足；脚本不自动无限重试 |
| 返回非 JSON | URL 可能是网页而非 API，或模型没有按格式输出 |
| 空响应/输出未完成 | 推理占用预算、被内容策略拦截或模型不兼容 |
| 当前题目包含图片 | 请给图片用途选择支持图片输入的接口，保存并测试后重新开始 |
| 字体加载或截图生成超时 | 刷新后检查题目和图片是否正常加载，再重新开始；本次不会提交 |
| 题目图片读取失败 | 图片损坏、超时、跨域未授权或来源不能读取；检查预览，不会继续随机提交 |
| 连接失败 | 检查网络、油猴对目标域名的授权和 HTTPS 地址 |
| 专题计时不增长 | 保持阅读标签在前台、有焦点，确认没有手动暂停或进入夜间休息；检查原课程仍在运行 |
| 文档滚动无法确认 | 检查内部阅读器是否加载、跨域页面是否启用脚本；按提示手动处理未完成任务点 |
| 页面已答对仍停住 | 确认最新版、没有手动停止/处于夜间；看面板具体原因；点击继续只允许一次，平台未响应先恢复一次，再失败记录跳过 |
| 文档没有完成标记 | 预览可能跨域、任务规则不同；60 秒停留不等于保证任务点完成 |

反馈时请提供面板提示、服务商、协议和模型名，并按需附上脱敏截图或页面结构。不要上传 Key、连接码、Cookie、完整课程链接或油猴存储导出。
